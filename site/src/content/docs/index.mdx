After [sluice](https://agentplot.github.io/sluice/) lands a change, tailrace
versions, packages, signs and pushes what the build left as OCI artifacts
into a registry you own: ECR, GHCR, Harbor, zot, or a file-based OCI layout
on disk. To each artifact's digest it attaches attestations as OCI
referrers: the build's provenance, sluice's signed check verdicts for the
landed commit, and the test results. The bytes that passed the gate are the
bytes that run. Your artifacts, in your account.

[The roadmap](/tailrace/roadmap/) orders the work of building it.

## One store, three jobs

A cache hit, an artifact and a release are the same content-addressed bytes
at three levels of trust. tailrace keeps them in one store, so nothing is
rebuilt on its way to production.

## What it never does

tailrace never rebuilds an artifact on its way to a release: the digest the
merge queue signed is the digest a channel points at. A machine an agent
runs on writes only to the cache and to quarantine, and never promotes.
A consumer is never served a version whose attestations fail the policy.
And tailrace never holds your artifacts: the registry is yours, and
tailrace keeps no copy of it.

## Where you meet it

One core answers every surface the same way, so a person at the command
line, an agent in its session and a pane beside the agents all see one
answer: what each landing published, where each channel stands, and what
every environment runs.

## Its first user

The family's own repositories, which sluice already lands, run tailrace
first: a file-based OCI layout on disk, ECR as the registry, moon's remote
cache backed by the store, and `beta` and `stable` channels moved from the
command line with signed promotion records.
