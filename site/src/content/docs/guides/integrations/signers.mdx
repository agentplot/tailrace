tailrace signs only as the party running it and only what that party
observed; a claim another party made is carried as made, never
re-signed. A signer's identity is bound to the party that holds it and
expires with that party's standing; a signature by an identity that has
expired is reported as such, never as valid and never as absent (81).

## The contract

The seam is two operations (79, 80). **sign** takes a claim and the
identity of the party running tailrace and answers the claim signed, or
that no identity is at hand. **verify** takes an attestation and the
signers a policy names and answers which signer made it, or that none
of them did. A claim counts for a verdict only through a signer the
policy names and a claim that signer may make, never through what the
claim says of itself.

## Members

| member | profile | how | status |
|---|---|---|---|
| a key in AWS KMS | C.7, a key in a key service | a key the host's cloud identity may use and never export, through the host's role; the signer's name is the key's, and verification uses its public half | built |
| a host key | C.8 | a key file on the host, as sluice's signers hold theirs, read at each signature and kept nowhere; verification uses the public key the policy lists | built |
| keyless with Sigstore | C.9 | a short-lived certificate bound to an identity from the owner's identity provider, logged in a transparency log, as Sigstore issues and cosign uses, public or private | designed |

The operator binds the signers for a host (92). A machine an agent runs
on holds an offering signer; the gate holds the accepting one; and no
host configuration holds both.

### The host key

The host key takes an Ed25519 private key in OpenSSH's format, with no
passphrase, that only its owner may read (mode 0600): the same kind of
key sluice signs its run records with. Make one with:

```sh
ssh-keygen -t ed25519 -N '' -f <path>
```

A key others may read, one with a passphrase or one of another
algorithm is refused, saying which. A claim is signed as an SSH
signature over the envelope's DSSE pre-authentication encoding, in the
namespace `tailrace-claim`, so no signature made for git or for sluice
verifies as a claim.

To verify, the policy lists for the signer its public key, in
ssh-keygen's allowed-signers form without the principal, since the
signer's name is the principal: `ssh-ed25519 AAAA… host@laptop`. The
listing may carry OpenSSH's `valid-before="YYYYMMDDZ"` (or
`YYYYMMDDHHMM[SS]Z`), a time in UTC; after it, a signature by the key is
reported as made by its signer and expired. A machine that verifies
holds no key file: verify reads only what the policy lists, and the name
an envelope gives its signer decides nothing.

The host key is bound by the host's bindings file's `[signing]` table,
sluice's own shape: `signer`, the identity it signs as, and `key`, the
key file's path, absolute or beginning `~/` (see
[self-hosting](/tailrace/guides/self-hosting/)). A host whose file names
no `[signing]` binds the host key verify-only: it tells every claim by
the keys the policy lists, and answers every sign absent, saying no
identity is at hand, reading no file.

### A key in AWS KMS

The key service signer takes an asymmetric KMS key of the key spec
`ECC_NIST_P256` and the key usage `SIGN_VERIFY`, whose key material KMS
made: the private half never leaves KMS, and the host signs with nothing
on its disk. Make one in the account the fleet runs in:

```sh
aws kms create-key --key-spec ECC_NIST_P256 --key-usage SIGN_VERIFY \
  --description "tailrace signer for the build fleet"
```

A key of another spec or usage is refused, naming it, and so is a key
whose key material was imported (origin `EXTERNAL`) or is held in an
external key store, since its private half was outside KMS once.

The key's name is its key ARN,
`arn:aws:kms:<region>:<account>:key/<key id>`, and nothing else: an
alias can be moved to another key, so neither an alias nor its ARN
names a signer. The signer's identity, the envelope's signer and key id,
and the region KMS is reached in all come from the ARN.

Grant, in the key's policy:

- the signing host's role `kms:Sign` and `kms:DescribeKey`;
- every account and role that verifies `kms:GetPublicKey` and
  `kms:DescribeKey`, the gate's and each consumer's among them.

The host signs through its own AWS credentials, found as the AWS tools
find them at each signature: the environment, the AWS profile and its
SSO session, web identity, the container's or the instance's role.
tailrace keeps none of them (64). A claim is signed by KMS with
`ECDSA_SHA_256` over the SHA-256 of the envelope's DSSE
pre-authentication encoding, so cosign and other verifiers that take a
KMS key read the same envelope.

Bind it in the host's bindings file's `[signing]`, alone:

```toml
[signing]
kms = "arn:aws:kms:us-west-2:111122223333:key/1234abcd-12ab-34cd-56ef-1234567890ab"
```

and list it in the policy by the same ARN:

```toml
[signers.fleet]
kms = "arn:aws:kms:us-west-2:111122223333:key/1234abcd-12ab-34cd-56ef-1234567890ab"
kinds = ["provenance"]
```

Every host binds the key service signer, verify-only where its file
names no KMS key, so a laptop with a host key verifies a fleet's
claims. verify reads the key's public half and its state from KMS each
time; an envelope with no KMS signature, a host key's, is refused
without reaching KMS. A host with no AWS credentials that may read the
key answers unreadable, naming the key, never a pass.

To retire a key, disable it: its signatures are reported as made by
their signer and expired (81), and still count where they counted when
they were accepted. Enable it again and they are reported not expired.
Never schedule a key's deletion while anything it signed is in use:
once deletion is scheduled, KMS gives out its public half no more, and
every claim it signed is answered unreadable.

## Adding one

A signer profile implements the one signer interface and nothing of the
core. It passes the one conformance suite, which holds it to Parts A and
B; a profile that fails the suite is not one (93).
