A build is a run of the repository's own commands over one revision
that leaves outputs. tailrace never builds; it asks the build seam to
make sure an output exists and to say where it came from. The same
revision and the same inputs give the same build identity on every host
(76).

## The contract

The seam is three operations (74, 75, 139). **ensure** takes a revision
and the outputs the authors declare and leaves those outputs present for
that revision, or says the build could not make them, naming which.
**report** takes a revision and an output and answers the build identity
the output came from, the build's outcome, and where the output's files
are. **left** takes a checkout and answers the build identities whose
outputs that checkout's own build state holds, each with its tasks, its
outcome and where its files are, read from the build's own records and
nothing of tailrace's; a checkout that ran nothing answers an empty
list. A
publish reads every declared output's outcome before any artifact is
offered, and offers an output only when its build identity is one the
landing's verdicts name.

## Members

| member | profile | how | status |
|---|---|---|---|
| moon | C.3 | the repository names, in its policy file at the revision, the moon task that makes each output, `[build.outputs.<name>] task`; an output is that task's declared outputs; the build identity is moon's task hash, which sluice's verdict also carries; ensure is one run of the named tasks in a checkout of exactly the revision, replaying what is cached, and that checkout shares the outputs directory of the checkout tailrace runs in, as every checkout on a host shares it, so the cache entries a publish renders from the store are what moon replays; report reads moon's own record of the run; a task's output archive is a cache entry under its task hash: `tailrace push`, run on the landing host after the landing, writes the archives of the landing's passing tasks as cache entries, which needs the host's checkouts to share moon's outputs directory so the archives of a landing's checks outlive the place they ran in, and `tailrace sync` renders them into a checkout; left reads a checkout's own run report and the archives its outputs directory holds, naming each task hash archived there with its tasks and their declared files, and runs no task, so `tailrace push --left`, run in a check job's checkout before the landing, writes what that job's run made | built |
| a declared command | C.4 | where no task runner declares outputs, the repository declares, per output, the command, its inputs and the shell to run it through; the build identity is the git tree hash of the declared inputs at the revision | designed |

## Adding one

A build profile implements the one build interface and nothing of the
core, and is bound in the repository by its authors (92). It passes the
one conformance suite, which holds it to Parts A and B; a profile that
fails the suite is not one (93).
