The ledger is a chain per channel: every promotion is a claim the gate
signs that names the digest of the promotion it follows, so the chain is
ordered and tamper-evident wherever it is held (105). Where it is held
is a seam of its own, the ledger (B.8). The gate alone appends, so a person who promotes from
a terminal or a phone asks the gate, and the gate writes wherever the
ledger profile the operator bound says; nobody's device commits anything. The
same claims are attached in the store to the versions they move to, and
where the store disagrees with the ledger, the gate rewrites the store
from the ledger (106).

## The contract

The seam is two operations (120, 121). **append** takes a promotion
claim and the digest of the promotion it names as its predecessor, and
holds the claim at the head of its channel's chain, or refuses it naming
the claim at the head. **chain** takes a channel and answers every
promotion claim of it in order from the first, or that none is held. The
ledger never removes or reorders a claim, and answers the same chain to
every reader for as long as it holds it (122). Two claims that name one
predecessor are a fork, which the gate reports and never resolves by
choosing.

## Members

| member | profile | how | status |
|---|---|---|---|
| a git ref | C.13 | one ref per channel in the repository, `refs/tailrace/ledger/<channel>`, each commit holding one promotion claim; append is a push that fast-forwards, and a push the remote refuses is a predecessor that is not the head; the gate's own identity pushes | built, the default |
| the store | C.14 | the chain as the promotion claims attached to the versions they move to, walked by predecessor from the channel's name in the store, `channel/<channel>`; for a store the operator can trust to retain untagged claims, which a registry whose retention rules expire them by age is not | built |

The host binds one in its bindings file, `[ledger] git_ref = { remote =
"origin" }` or `[ledger] store = {}`; see
[self-hosting](/tailrace/guides/self-hosting/).

## Read as last read

Where the source holding a chain does not answer, the chain is answered
as this host last read it, saying when and carrying the source's own
words, and nothing is appended to it or moved from it (60, 61).

- **The git ref.** Every read fetches the remote's ref into the
  repository's own copy, which only moves forward; a remote that no
  longer extends the copy is a fork, or a loss of the claims it no
  longer holds, and is reported, never chosen. Where the remote does not
  answer, the chain is the copy's, as of the last time this repository
  fetched or wrote it, from its reflog, with git's words.
- **The store.** Every chain the host reads is kept, with the time it
  was read, in `tailrace/ledger/<channel>.json` under the repository's
  common git directory, beside the record of published versions. Where
  the store does not answer, the chain is that file's, with the store's
  words. The file holds the chain and nothing else.

A hosted backend binds its own append-only log as its ledger; the chain
is the same bytes, so it moves between profiles by copying claims.

## Adding one

A ledger profile implements the one ledger interface and nothing of the
core, and is bound for a host by the operator (92). It passes the one
conformance suite, which holds it to Parts A and B; a profile that fails
the suite is not one (93).
