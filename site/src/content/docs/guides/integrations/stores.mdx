A store holds bytes by digest, never alters them, and answers the same
bytes for the same digest for as long as it holds them; one that cannot
is not a store (73). Exactly one store is written by a publish (92).

## The contract

The seam is seven operations (66 to 72). **put-bytes** takes bytes and
their digest and says whether the store held them already; the same
bytes put twice are held once. **put-artifact** takes an artifact's
metadata and the digests of its bytes and answers the artifact's digest,
which the store names it by thereafter. **attach** puts an attestation
beside a digest, where **claims-of** reads every attestation attached to
that digest, as attached, or says the digest is not held. **name** moves
a name to a digest only from the digest it is expected to be at, and
otherwise refuses, naming the digest it is at; a name moved from nothing
is a name made. **resolve** answers the digest a name names, or that it
names nothing. **read** answers a digest's bytes, or that the digest is
not held.

## Members

| member | profile | how | status |
|---|---|---|---|
| Amazon ECR | C.1, an OCI registry | over the distribution protocol, everything in one declared repository; the credential from ECR's helper; proven by hand, outside the gate, by a push on 2026-10-25 | built |
| GitHub Container Registry | C.1 | the same, under the owner's packages | designed |
| Harbor | C.1 | the same, in a project of the operator's | designed |
| zot | C.1 | the same, on a host or on object storage, attestations listed by its referrers API; proven in the gate | built |
| the reference distribution | C.1 | the same, the smallest registry, with no referrers API, so attestations are listed by the referrers tag; proven in the gate | built |
| an OCI layout on disk | C.2, an OCI image layout | a directory, every operation a file write under the digest's path; an artifact is an OCI manifest, an attestation an entry of `index.json` annotated with its subject, and a name an entry with a ref name, moved only from where it is | built |

A registry holds everything in the one repository the host names, such
as `<account>.dkr.ecr.<region>.amazonaws.com/tailrace` or
`localhost:5000/tailrace`, addressed by digest, and the store never makes
a repository. An artifact is an OCI manifest whose artifact type names
the ecosystem, whose layers are the ecosystem's own bytes and whose
config is its own metadata, in exactly the bytes the layout writes, so
one artifact has one digest in both (1). An attestation is a DSSE
envelope holding an in-toto statement, attached as a referrer of the
digest it is about: a manifest typed by tailrace's envelope type, its one
layer the envelope, the statement's predicate type in its
`in-toto.io/predicate-type` annotation. claims-of lists the subject's
referrers of that type by the referrers API, or, where a registry has
none, by the referrers tag the distribution specification defines in its
place. A name is a tag, the name escaped into one. No registry refuses a
tag put by the digest it is expected to be at, so name reads the tag
first and refuses a move from anywhere else as far as that read shows,
and reads it back after the put, again while the registry still answers
the former place, for up to 30 seconds: a tag found at another digest is
a lost race, refused naming that digest and never retried (70, 109). A
read can lag a put, as ECR's do, so nothing rests on the check: a
channel's name found elsewhere is repaired from the ledger (109). A tag names only a manifest, so a
cache entry's bytes are named through a cache manifest whose one layer
is the bytes, and resolve answers the bytes' digest (100); a cache
manifest is no artifact, and claims-of never lists it. The credential is
the host's, from its Docker configuration and the credential helpers it
names, reached when the registry asks for one and kept nowhere (64).

zot and the reference distribution are proven in the gate, each started
for the test. ECR needs a person's live AWS session, which the gate does
not hold, so its run is a check of its own outside the gate, run by hand
with `moon run ':#check-ecr'` against a repository the host names. ECR
was proven by that run's push on 2026-10-25, in us-west-2; ADR 0015
records what ECR answered.

The layout is bound for a host by its bindings file, `[store] layout =
"<path>"`, and a registry by `[store] registry = "<host>/<repository>"`
(see [self-hosting](/tailrace/guides/self-hosting/)). A host with no
file, or a file with no `[store]`, binds the layout at
`~/.local/share/tailrace/layout`, under `$XDG_DATA_HOME` where it is
set, and names it in its record by that path in full (118, C.2). A
publish makes the layout, the given one with its parents, the first time
it asks the store anything, where the path is missing or an empty
directory, and writes into it thereafter, so a publish refused before it
asks the store makes none;
verify and status never make or write one, and answer a layout that is
not there unreadable naming its path; nothing makes a registry's
repository.

## Adding one

A store profile implements the one store interface and nothing of the
core, and is bound for a host by the operator (92). It passes the one
conformance suite, which holds it to Parts A and B; a profile that fails
the suite is not one (93).
