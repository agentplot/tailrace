# timber rules

The rules that bind wherever a change is made in this repository,
written so a reviewer can point at a diff and say which rule it breaks.
The narrative is the statement in agentplot/blueprints,
`design/timber/requirements.md`; a rule here names the clause it
enforces and never restates it. There are no area pages yet; a rule
that binds only one part of the tree moves to an area page when that
part exists.

## Rules

### The core and its seams

- **[core.1]** Code outside a profile or a plugin directory names no registry, task runner, merge queue, key service, package manager, deploy target or forge.
- **[core.2]** Every seam of Part B is reached through exactly one interface, and a profile implements that interface and nothing of the core.
- **[core.3]** A seam with a single profile has an ADR saying why one is enough.

### Bytes and digests

- **[core.4]** No code path acts on a name: every operation resolves a name to a digest first and records the digest it acted on.
- **[core.5]** No code path writes bytes under any digest but their own, or rewrites bytes a store holds.
- **[core.6]** A name is moved only with the digest it is expected to be at, and a refused move is reported, never retried blind.

### Claims

- **[core.7]** A claim counts for a verdict only through a signer the policy names and a claim that signer may make, never through what the claim says of itself.
- **[core.8]** timber signs only as the party running it and only what that party observed; a claim another party made is carried as made, never re-signed.
- **[core.9]** Every claim timber writes names the revision it is about, and the build identity where it has one.
- **[core.39]** A signature by an identity whose standing has lapsed is answered made and expired, never valid and never absent, and a claim that counted at acceptance keeps counting.
- **[core.40]** A signer's name names one key and never moves; no alias and no name a provider may point at another key names a signer.
- **[core.41]** A key-service signer signs only with a key whose private half never left the service; imported material and an external key store are refused at sign.
- **[core.42]** A signer the policy lists that cannot be read is unreadable naming it, never passed over.
- **[core.57]** Every claim timber signs takes the kind the public catalogue of claim kinds defines for what it says, and a kind of timber's own only for a claim the catalogue carries none of.
- **[core.58]** A bundle of claims is verified under a trusted root timber is given, its certificates, inclusion proofs and passkey assertions, with no call to any service.
- **[core.59]** Another system's trusted root counts as a signer only where the policy names it and for the kinds it lets that root's signers claim, and a claim under it is checked against the root as it stood when the claim was made.
- **[core.71]** A report is signed only by the host that ran the apply, only after the target's report names the index applied, and only beside that index.

### Publishing

- **[core.10]** No code path reachable from publish offers bytes whose build identity the landing's verdicts do not name, builds what it offers where the landing has verdicts, accepts, promotes, moves a channel or reaches a target.
- **[core.11]** A publish refuses a revision the landing seam has not landed, before anything is read or offered.
- **[core.12]** Every declared output's outcome is read before any artifact is offered, and the index is offered last.
- **[core.13]** The version's name is derived from history by the authors' rule and claimed in the shared history before any artifact is packed, and no build is handed a version.
- **[core.37]** A version is derived for one declared component over the commits that touch its paths and the tags that carry its prefix, and no code path derives a version, claims a name or moves a channel without naming the component.
- **[core.52]** The core starts nothing after an offer or a landing; what tells the gate is named in the host's bindings file and nowhere in the core, and timber runs nothing for a job named there.
- **[core.60]** A publish names each artifact `artifact/<ecosystem>/<name>@<version>` at the digest of its version's index, beside the component's tag and moved only with the digest it is expected at; no component's tag enters `artifact/`, `cache/` or `channel/`, and the index names the publishing repository by its remote's owner and name and the revision.
- **[core.61]** A version's notes are rendered by the version rule's own tool under the repository's own template from the history that derives the version, are an artifact its index names, and are written by nothing after the offer; a surface derives them from the landed history and asks no store for them.
- **[core.62]** A host pushes the cache entries of the tasks it ran, which the build seam's `left` names, as cache entries and nothing more; a pool job's push holds a credential that writes cache entries and nothing else in the store.
- **[core.70]** A Nix closure enters the store as one artifact naming its roots, and no store path of it is an artifact or a cache entry; its paths are the Nix binary cache's.

### Acceptance and channels

- **[core.14]** Only the gate's path accepts or promotes, and no code path holds both an offering credential and an accepting one.
- **[core.27]** An attestation is written only beside the digest it is about, and no code path keeps one apart from its digest.
- **[core.28]** A version with one refused artifact is refused whole, naming the artifact, and no code path accepts part of a version.
- **[core.29]** A reconciler verifies the claims it is told to require before any apply, and no apply path skips the verify.
- **[core.15]** A promotion is written to the ledger before the channel is read as moved, and nothing deletes or rewrites a ledger entry.
- **[core.16]** A channel moves only from the version it is at, and an environment is never handed a version except through its channel.
- **[core.34]** A promotion is appended to its channel's chain only after the claim it names as predecessor is the chain's head, and two claims naming one predecessor are reported as a fork, never chosen between.
- **[core.35]** No code path converges an environment that waits except by a promotion of the channel it follows; there is no approval that is not a promotion.
- **[core.43]** The core names no channel, and nothing but the policy profile reads a key of the policy file.
- **[core.44]** A line under a channel narrows who may ask or adds a claim its versions must carry, and never widens who signs; approvers never join who signs.
- **[core.45]** Nothing is appended, attached or moved from a chain read as last read, and nothing is signed or appended before every claim the channel's policy requires has been judged.
- **[core.46]** The asker of a promotion is a signer the gate verified, never a word the asker gives.
- **[core.47]** A ledger ref is never force-pushed and the repository's copy of it only moves forward; a remote holding less than the copy is unreadable naming the claims it lost.
- **[core.48]** A channel's store name is under `channel/`, made by the seam's one function, and is never a version's, a prefix's, an artifact pointer's or a cache entry's.
- **[core.49]** A store profile declares whether its names take a condition, and the suite runs the stale-move refusal where they do and the repair where they do not; a tag read back at the former place is read again up to the profile's bound, a third digest refused at once, and the put never repeated.
- **[core.50]** A channel's head is read from its chain, never from a resolve of its store name.
- **[core.51]** No media type or artifact type the registry profile writes carries a parameter.
- **[core.63]** An act that asks several promotions appends each after its own predecessor; a ledger that can hold the appends as one refuses them whole when any one is refused, naming the chain, and one that cannot appends them in order and reports the first refused, the moves before it standing.
- **[core.64]** A database ledger appends a claim and moves its chain's head in one transaction conditioned on the predecessor, and rows a control plane keeps beside the chain are written in that transaction and read as projections.
- **[core.65]** An environment kind's instances are the target's roster and are declared nowhere in the repository; an instance that waits follows a channel of its own, named by the entry within its component and bound to the channel the entry names.
- **[core.72]** A channel an `after` makes is moved only to the index every environment it names last reported, read from counted reports across each one's chain, and by no asking but the gate's own.
- **[core.73]** A push to a Nix machine runs only the root its version's closure names, checked against the revision's evaluation and realised from substituters alone before the fleet's tool runs, and builds nothing.

### Consumers

- **[core.17]** A consumer layout holds only versions whose verdict under its policy is satisfied, and a refused version is reported naming the claim found wanting.
- **[core.18]** An address a client records names no host and no one owner's store.
- **[core.36]** One serving process answers a host, at one fixed name and port with the repository in the path, started by the first asker that finds none under the host's one lock, ending only when nothing has asked for a while and no layout is served; no checkout starts one of its own and no person is told to start one.
- **[core.56]** A page a surface renders is one HTML document with no script, every string escaped and every refusal in the source's own words.
- **[core.66]** The core closes a layout over what the projection answers a checkout pins and each held version requires, listing through the store and judging under the layout's policy at every level, and no core code reads a lockfile or a manifest.
- **[core.67]** A consuming repository's layout is rendered under its own layout policy at its landed revision where its file writes one, else under the publisher's layout-policy claim its version's index carries, else under the given, every part read from the store.
- **[core.68]** The pane reads the served page's own answer and shows one repository or every repository the host knows, at the viewer's choice, as the page answers them.

### Answers and records

- **[core.19]** Absent, refused and unreadable are three answers, and a refusal carries the refusing source's own words verbatim.
- **[core.20]** Every record a reader may need is readable with no timber process running, and everything kept but the record of claimed versions is rebuilt from the store and git.
- **[core.21]** No credential is kept: a credential is the asker's, the host's or the environment's, reached at the moment of use.
- **[core.22]** The policy is read from a landed revision of the branch it governs, never from a checkout.
- **[core.30]** No code path but a publish makes an artifact of a cache entry's bytes, and none names a cache entry from a channel, an index or a policy or refuses to build because one is gone; a publish that finds no entry for an identity the verdicts name is refused naming the output, never built for.
- **[core.69]** A compilation's cache below the task is the toolchain's and the host's: timber carries none of it between hosts and names none, and a verifier's rebuild reads none another party wrote.
- **[core.31]** Every surface calls the one core and renders its answer; no surface computes a verdict, a version or a channel of its own.
- **[core.32]** A read of what timber holds opens no connection to a signer or a target, reaches a store only to fetch a chain it holds or an environment's reports into the host's copy, and writes nothing but that copy.
- **[core.33]** Every profile passes the one conformance suite, and every scenario of the suite cites the clauses it exercises; a clause no scenario cites is named in the suite's register with the unit of the plan that will cite it, or with the phase of the plan while that phase has no units carved, and why, and leaves the register with the commit that cites it.
- **[core.53]** A bindings table the file leaves out is bound to its given; a file or table that is there and cannot be read is unreadable naming it and binds nothing given in its place.
- **[core.54]** The configuration directory holds nothing timber made; the given key is made only by a sign, and a key file that is there is never replaced.

### Design and records

- **[core.23]** A change that bears on a clause cites the clause by number; a clause that no longer holds is changed in the statement first, never worked around here.
- **[core.24]** Nothing commercial, no pricing, tier, hosted plan or customer, appears in this repository.

### The gate

- **[core.25]** Every file the tree tracks is owned by a formatter the gate runs, or is excluded by name with its reason; every language with a linter is linted; `site/`, and every crate and plugin directory, is a moon project of its own whose check-fast tasks validate, type-check and test it, one task per check.
- **[core.26]** Every tool a gate task runs is the version the tree pins, on every host that runs the gate.
- **[core.38]** No gate check needs a credential a person signs in for or a service only such a credential reaches; a check that does runs outside the gate, by hand with a live session or by a job that holds an identity of its own, under a tag of its own, refusing to run without its setting and naming it.

## Details

- **core.1** Rules out: the strings `oci`, `ecr`, `ghcr`, `oras`, `cosign`, `moon`, `sluice`, `kms`, `npm`, `maven`, `cargo`, `flux`, `gh` in any source module outside a profile directory or a plugin directory; an import of a profile from the core. Not ruled out: `git`, which section 9 of the statement fixes, except in the ledger's code, which reaches where the chain is held through the ledger seam (B.8) and names no git; the in-toto and DSSE forms, the givens' default for every attestation, and the catalogued kinds section 9 gives each claim (141); `.moon/` and the other configuration of this repository's own checks, which are no module; a plugin, which is a surface outside the core and names the ecosystem command it refuses. Source: statement preamble, clauses 92, 141; ADRs 0002, 0003, 0005, 0022.
- **core.2** Rules out: a profile calling another profile; a core function with a profile-specific branch; a projection that reaches the store other than through the store seam. Source: clauses 92, 93; ADR 0002.
- **core.3** Rules out: a seam whose only profile is undocumented as such. Source: ADR 0008.
- **core.4** Rules out: reading a tag, a version or a channel and acting on what it names without resolving it; a record of an act that names a tag and no digest; a channel head read to decide what to deploy without the digest beside it; a gate told of a version by a publish that judges a digest other than the one the telling named (95). Source: clauses 3, 40; ADR 0003.
- **core.5** Rules out: a put under a digest computed from anything but the bytes; a copy that recompresses or rewrites; an "update" of an artifact's bytes. Not ruled out: packing the same outputs with a new version, which makes a new artifact with its own digest (24). Source: clauses 1, 2, 73; ADR 0003.
- **core.6** Rules out: a tag put without the expected digest where the store supports one; a loop that re-reads and retries a refused move; a channel moved without reading what it is at. Not ruled out: on a store whose names take no condition, the tag read again after its put up to the profile's bound with no second put, the check best effort (C.1; ADR 0015). Source: clauses 35, 70, C.1; ADRs 0007, 0015.
- **core.7** Rules out: a verdict that counts a claim because its predicate type is right; a signer's claim counted beyond what the policy lets it claim; a verdict that trusts a carrier's word that it verified what it carried. Not ruled out: keeping every claim attached, counted or not (9). Source: clauses 9, 80; ADR 0007.
- **core.8** Rules out: signing a provenance for a build this host did not run; re-signing sluice's run record under timber's key; a claim in a reviewer's or a gate's name made on their behalf. Source: clauses 11, 12; ADRs 0005, 0025.

- **core.10** Rules out: a publish that runs the build's commands itself rather than asking the build seam; an output offered whose build identity no verdict of the landing names, where the landing has verdicts; a publish that builds an output it offers, through the build seam or otherwise, where the landing has verdicts, on a host that holds the outputs or one that holds none of them (135, I3); a publish that moves `beta` because the policy says `beta` follows each publish, which is the gate's (95); a publish that syncs a bucket or updates a stack. Not ruled out: on a host that holds the outputs, reading them where the build seam's report says they are (75); on a host that holds none of them, reading from the store the cache entries whose build identities the verdicts name and offering those bytes (135); where the landing has no verdicts (C.6), the publish's host building through the build seam, which may run the repository's own tasks (74), and offering what it left as its own (135). Not ruled out: the host's publish step telling the host's own gate of the publish's answer where the host's bindings file names it, whose judgment and moves are the gate's (95, 108, 130). Source: clauses 15, 20, 75, 95, 108, 130, 135; ADR 0002, 0004, 0020.
- **core.11** Rules out: publishing a session's head, a candidate under test or a worktree's tree; checking the landing after artifacts are offered. Source: clause 14; ADR 0004.
